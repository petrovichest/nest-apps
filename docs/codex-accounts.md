# Аккаунты Codex

CodexNest использует общий с ClaudeNest интерфейс аккаунтов и мастер подключения:
разбор адреса, HTTP/HTTPS/SOCKS5, проверка и копирование прокси, явный выбор прямого
подключения, повторный вход, удаление, автопереключение и прогрев лимитов.
Авторизацию и обновление токенов выполняет native Codex. Пароли аккаунтов и
реализация OAuth в Nest не дублируются.

## Подключение и владельцы сессий

- Новый аккаунт требует выбора подключения до начала device-code OAuth.
- При импорте старой конфигурации сохраняется прежний глобальный прокси.
  Некорректные настройки блокируют использование аккаунта; они не означают
  разрешение подключиться напрямую.
- Для аккаунта и поколения его подключения запускается отдельный native процесс.
  У него собственные credentials, кеш моделей и неизменяемый маршрут через
  приватный локальный relay. SOCKS5 использует разрешение имён на прокси.
- Relay требует случайные локальные credentials. Ошибки upstream, авторизации,
  DNS или соединения не переключают его на прямой маршрут. Унаследованный
  `NO_PROXY=*` удаляется; исключения ограничены loopback для локальных сервисов.
- Выбор аккаунта меняет предпочтение для новых сессий. Запущенные задачи сохраняют
  владельца и подключение. Изменение прокси требует завершения ответов только
  соответствующего аккаунта. Повторный вход создаёт новое поколение credentials,
  сохраняя прежнее для выполняющихся задач.
- История и native SQLite общие; credentials остаются раздельными. В реестре Nest
  сохраняется владелец каждой сессии. API переподключается к пережившим его
  процессам и повторно подписывается на события без повторной отправки сообщения.
- Production использует отдельные `codexnest-account-<uuid>.service` через
  существующий пользовательский systemd. Остановка API не останавливает эти units.
  Они не заменяют и не перезапускают исходный daemon пользователя.
- Удаление записи не удаляет историю, поколения credentials или выполняющуюся
  задачу. Служебные метаданные сохраняются для завершения прежнего владельца.

Гарантия маршрутизации относится к запросам самого Codex: модели по HTTPS/WSS,
модели и плагины при обнаружении, device OAuth, refresh token и лимиты. Это не
сетевая песочница для произвольных команд и программ агента. Страница ChatGPT,
открытая пользователем, использует подключение его браузера.

## Лимиты и продолжение работы

Автоматический выбор предпочитает доступный аккаунт с ближайшим сбросом
пятичасового окна. Учитываются недельные лимиты, дополнительные квоты моделей,
ошибки подключения и авторизации. Обычный запуск сообщения не добавляет RPC для
определения аккаунта. Лимиты опрашиваются отдельно, с общим запросом при
конкурентном обновлении и повторной проверкой после сброса окна.

После подтверждённой native ошибки квоты или авторизации продолжается та же
история с другим доступным аккаунтом. Используется существующий механизм
надёжной доставки и отдельный маркер продолжения. Исходный запрос пользователя
повторно не отправляется; модель, режим, настройки, очередь и результаты
сохраняются. Неопределённая доставка сначала сверяется с native историей.
Отключение автопереключения или остановка задачи отменяет такое продолжение.

Прогрев доступен отдельным переключателем и изначально выключен: короткие
запросы расходуют лимит. Свободные подписки прогреваются с разнесением окон
на пять часов по тому же расписанию, что в ClaudeNest. Занятые аккаунты
пропускаются. После перезапуска API прогрев не запускается при health check;
его разрешает явное включение или последующая пользовательская работа при
ранее сохранённом выборе.

## Проверки и выпуск

Native проверки используют настоящие бинарники Codex 0.154.0 и 0.167.0,
синтетические credentials и собственные HOME/state/порты. Они проверяют:

- два аккаунта с двумя разными инструментированными прокси;
- HTTPS и WebSocket через HTTP-, HTTPS- и SOCKS5-прокси;
- отказ авторизации прокси и отказ TCP при доступном напрямую сервере модели;
- OAuth, refresh token, лимиты и продолжение истории после исчерпания квоты;
- сохранение native PID, владельцев и работы при переподключении API;
- отсутствие изменения авторизации исходного daemon.

Запуск отдельного native набора:

```sh
NODE_ENV=test CODEXNEST_ACCOUNT_CODEX_BIN=/path/to/isolated/codex \
  npm run test -w @codexnest/server -- \
  src/account-proxy.integration.test.ts src/codex-accounts.integration.test.ts
```

CI запускает этот набор для обеих закреплённых версий и сохраняет отчёт,
связанный с SHA кандидата. При обычном запуске unit-тестов native набор
пропускается; такой запуск не доказывает маршрутизацию.

Эти проверки не заменяют полную матрицу установки, большой истории, обновления
старым обновлятором и автоматического отката из [release-safety.md](release-safety.md).
Задача `release-qualification` намеренно закрывает публикацию до реализации
и подтверждения всей матрицы. Зелёный PR аккаунтов сам по себе не разрешает
выпуск приложения.
